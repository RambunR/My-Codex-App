# iPhone Safari playback audit — 14 November 2026

The reported failure was **the website opens, but dramas do not play**. Read-only inspection found the first public episode of all 21 series advertised H.264 High Profile Level 6.2 with an implausible SPS/VUI decoder clock, despite ordinary 25/30/60 fps MP4 sample timelines. The representative 720 × 1280 episode reports a 16,000 fps non-fixed decoder clock. Chromium displayed it; WebKit produced no decoded picture (`videoWidth: 0`) and `MEDIA_ERR_DECODE` (code 3) on a seek. Serving the same encoded pictures with corrected AVC configuration/SPS metadata produced visible 720-pixel frames and a successful seek.

## Delivery correction

`shared/mp4-playback.ts` inspects bounded MP4 metadata and corrects only this identified export pattern. Its guards require one `avc1` video track, 8-bit 4:2:0 progressive High Profile, matching coded/display dimensions, supported near-constant sample cadence, bounded compressed samples/reference buffers, no HRD schedules, and an implausible non-fixed original VUI clock. It selects Level 4.1 or 4.2 from the verified macroblock rate/frame/buffer limits. A non-fixed nominal 24/25/30/50/60 fps decoder clock replaces the contradictory clock; the MP4 presentation timestamps, including fractional cadences, are untouched.

An exactly equivalent clock fraction preserves the escaped SPS length. If a safe correction cannot preserve every byte offset, the original stream passes through unchanged. Unknown codecs, genuine higher complexity, interlaced/high-bit-depth layouts and malformed metadata are never blindly labelled compatible. This is not a general transcoder or a guarantee that every future uploaded file is supported on every device.

The AVC configuration/SPS changes are applied only to overlapping delivered chunks in both the Node and Cloudflare storage adapters. All other bytes, encoded pictures, audio, upload files, object keys, storage quotas and database records remain intact. There is no media migration, duplicate rendition, new bucket, financial mutation or payment-mode change. Existing authentication, purchased/Lucky Draw access, moderation and publication checks run before streaming.

Metadata reads are capped at 4 MiB, top-level and child-box counts are bounded, sample loops are bounded, and cache entries retain only tiny byte patches. A 64-entry cache coalesces reads and is keyed by the actual object ETag (local file size/mtime/ctime in Node); transient read failures are not cached. Stream backpressure and cancellation are preserved. GET, HEAD, the Safari `bytes=0-1` probe, mid-metadata requests, seeks and suffix ranges retain coherent lengths and offsets. Video responses expose `X-LingYing-Playback: h264-compat-v1` and `X-LingYing-Video-Compatibility: normalized|original` for read-only rollout verification.

Safari storage blocking also no longer crashes language initialization or changes: failed browser-storage reads/writes fall back to the in-memory language state, while document language/direction still update.

## Verification scope

- The correction was evaluated against metadata from the first and last free episode of **all 21 currently public series**, including 25/30/60 fps variants. All **42 samples** matched the guarded correction. The public catalogue currently contains 637 free and 233 paid episodes; this sample does not claim every episode was downloaded or played. Paid streams were not fetched or bypassed during the live audit.
- Six focused media tests check decoded-frame hashes, unchanged audio and presentation packets, exact original storage, fragmented streams/ranges, HEAD/416 responses, end-of-file metadata, 25/fractional/60 fps, Level 4.2 bounds, malformed/unsupported inputs and cache invalidation/retry.
- Actual WebKit phone-context tests exercise decoded frames, seeking, pause/resume, next-episode navigation, the paid sign-in gate and browser-storage denial. Run `npm run test:safari` after installing the matching Playwright WebKit browser/dependencies. This uses WebKit on Linux, **not physical iPhone hardware or an Apple certification**.
- The Cloudflare integration regression uploads a disposable legacy export through the real local R2/SQL pipeline, independently compares delivered codec metadata with FFmpeg, checks unchanged encoded payload/quota, verifies private/public access and ranges, and repeats after runtime restart. It creates no production resources.
- Before rollout, all 570 unit/API tests, 38 focused storage/media regressions, three WebKit phone tests, the Cloudflare build and actual local SQL/R2 integration passed. Broader browser and live deployment results are recorded with the release. Production checks remain read-only: no real account creation, forged login, lucky draw, paid unlock, charge, transfer or payout. Browser analytics writes during live diagnostic playback are intercepted, avoiding synthetic production views.

Final release verification: **all 388 browser regressions passed**, and the three dedicated WebKit phone tests passed again against the final source. The existing Worker was updated in place as version `ee9826f3-5d6b-4f39-900e-e661141c88ea`, source `ca64a488dfc2dbed9bef52bd403ba25eb94ff417`. Live API checks verified exact corrected codec bytes, unchanged payload bytes, HEAD/ranges/416, protected paid access, health, prior/current assets and the unchanged existing database, media bucket, encrypted bindings and payment settings. All 42 sampled live video endpoints returned successful normalized byte ranges after rollout.

Live native WebKit and Chromium phone contexts decoded the real 720 × 1280 episode and resumed playback after seeks to both 25 and 50 seconds, with no media or page errors. Native media requests were left untouched; only application fetch mutations for diagnostic analytics were intercepted. Playwright network routing disables HTTP caching and affected repeated-seek diagnostics, so it was excluded from that live media check. The owner then confirmed that video **plays normally on their actual iPhone in Safari** after reloading. The iPhone model/iOS version, every paid episode, every device and live financial settlement were not independently verified by this feedback.

For future exports, use browser-ready 8-bit H.264/AVC and AAC in MP4, a realistic matching frame-rate/level declaration, and preferably fast-start metadata. Genuine unsupported encodings need a compatible export; changing a codec label is insufficient. Keep the existing five-minute / 200 MiB ordinary episode policy and the separate owner duration exception intact.

## Production readiness limits

Successful browser tests and the owner's iPhone confirmation do not certify every phone, network or iOS release. Wider physical-device coverage, sustained load capacity and a complete backup/restore exercise remain separate checks. The audit does not enable services merely to make a status appear ready: public configuration currently reports live customer payments ready, creator payouts disabled, email delivery unavailable and WeChat website login unavailable. Google/Apple configuration flags are not proof of completed provider consent. Actual live paid settlement, bank settlement and manual refund/dispute reconciliation retain their documented verification/operational limits.
