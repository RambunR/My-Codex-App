# Search appearance and browser icon

The canonical public homepage is `https://lingyingdrama.com/`. Existing permanent page redirects send both HTTP hosts and `https://www.lingyingdrama.com/` to this HTTPS address. TLS-verified public requests and those redirects passed on 4 November 2026. A red shield beside a search result alone does not identify a certificate error; a browser extension or reputation service may supply its own rating. Check the warning's details before attributing it to TLS or declaring the site unsafe.

The existing operator-selected LingYing phoenix supplies a stable 192×192 PNG favicon at `/icon-192.png`. `/favicon.ico` packages the existing 32×32 and 192×192 PNG images without changing their artwork. Both remain declared in the document head. The public brand is LingYing, with 靈映, 灵映, LingYing Drama and LingYingDrama as genuine alternate names.

Public pages now return useful HTML before JavaScript executes. The anonymous discovery renderer provides actual published titles, descriptions and navigable series/publisher links, together with route-specific title, description, canonical, Open Graph and social metadata. The homepage includes real WebSite/Organization JSON-LD; series use TVSeries metadata without inventing ratings, views, video availability, licences or release dates. The same response is served to ordinary visitors and crawler user agents. The React application replaces the initial snapshot and maintains metadata during navigation.

Only published, available series with episodes enter discovery. Drafts, archived, taken-down, deleted and retired content are excluded even when the caller is signed in as an owner or administrator. Private account/authentication/Studio/admin/watch pages carry `noindex`; unknown or unavailable public series return HTTP 404 instead of an indexable empty shell. Discovery never requests a video stream, creates a view, charges money or exposes account IDs, emails, balances or storage keys. The company contact address and public publisher attribution remain public.

`https://lingyingdrama.com/sitemap.xml` is generated from the current public catalogue, including public series and publisher profiles. Above 1,000 series it becomes an index of `/sitemap-page.xml?page=N` documents. Publication and moderation changes update discovery without a static-file rebuild. `robots.txt` identifies this sitemap and permits public posters and the public configuration/catalogue/profile JSON needed for JavaScript rendering. Those JSON documents carry `X-Robots-Tag: noindex` so the public HTML pages remain the search documents; private APIs remain disallowed and authenticated. Blocking all API resources would let React replace the initial snapshot with a failed data fetch in Google's renderer. Neither XML nor crawler instructions may fall through to the SPA HTML shell.

State-derived HTML and discovery responses use `private, no-store` so private/moderated states are not preserved in a public page cache. Canonical URLs use trusted deployment configuration, never caller-supplied host parameters. Each public route retains its own canonical identity; do not put a homepage-only canonical in the shared HTML template. Rewritten bodies remove stale compression, length and validation headers.

The Cloudflare Worker consumes only a versioned anonymous discovery response from the existing Durable Object, strips caller credentials on that lookup and retains the existing assets/security pipeline. During Cloudflare's documented Durable Object update interval, an old API may not yet know the discovery endpoint. The Worker then serves a usable generic SPA shell with temporary `noindex`, rather than a false series 404 or a broken site. Verify the new API and rendered HTML after the update interval before declaring the release complete; do not reset the database to accelerate rollout.

After publication, the site owner should open [Google Search Console](https://search.google.com/search-console), select the `lingyingdrama.com` property, and:

1. Submit `https://lingyingdrama.com/sitemap.xml` under **Sitemaps**.
2. Use **URL inspection → Test live URL → Request indexing** for the homepage and representative public series pages.
3. Check the **Page indexing** report, last crawl, rendering and Google's selected canonical if the site is still absent from the expected query. A successful live fetch establishes crawlability, not inclusion in Google's index or a particular ranking.

A public Google verification TXT record was present during the 11 November 2026 audit. This does not establish access to a particular Search Console account, successful verification for that account, index coverage or sitemap submission. If the property is missing, add the domain property and follow Google's account-specific verification instructions. Never invent a verification value or overwrite unrelated DNS records. Deployment does not submit a Search Console request or guarantee indexing.

Google must recrawl the homepage and icon before search appearance changes. This can take several days to several weeks; eligibility does not guarantee icon display. Browser tabs can update sooner after a reload. A reputation warning supplied by a browser extension or another security provider requires investigation with that provider, independently of the site's favicon.
