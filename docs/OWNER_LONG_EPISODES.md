# Owner-only episode duration exception

Ordinary creators and unrelated administrators remain limited to five minutes per episode. The existing immutable platform owner account, associated with `jimmy.tsoi2001@gmail.com`, has no business limit on episode duration. The account's authenticated API uses `max_episode_seconds: null` to represent that exception. The 200 MiB input and stored-episode size limit remains in force.

The server grants the exception only when a series' actual `creator_id` matches the trusted `PLATFORM_OWNER_USER_ID` and that persisted account has the administrator role. An email supplied by a browser, public display name, managed publisher profile, unlimited storage flag or acting administrator does not grant it. Managed publisher profiles for the owner's own series inherit the exception because attribution does not change actual ownership. An owner administrator editing another creator's series still gets that creator's five-minute limit.

Creator Studio reads the authenticated user's limit for new drafts and the private series response's `owner_upload_limits` for existing series. A missing capability from an older API defaults to five minutes; explicit `null` means unlimited. The upload guide displays the applicable duration policy and the unchanged size limit. Public Pass and ordinary creator copy continues to describe five-minute uploads.

Both direct and chunked uploads pass the server-selected duration policy to authoritative media validation, retain container/codec/dimension/size checks, and recheck current owner privileges in the final transaction. Browser-supplied duration or privilege fields cannot bypass it. Failed validation keeps existing cancellation, orphan cleanup and quota accounting. Node processing retains its bounded conversion queue and timeout and rejects a processed output over 200 MiB.

Long durations and watch totals use new additive `episode_durations_long` and `playback_session_times_long` tables. Existing 180-, 240- and 300-second constraints, purchases, ledgers and media remain intact. SQL helpers read the authoritative longest tier, while writes to older mirrors remain within their original bounds. A numeric representation guard keeps playback milliseconds within JavaScript's safe integer range; it is not a practical episode-duration policy.

Public viewing, resume progress, analytics and private previews use the actual persisted episode duration for every viewer. Existing credit remains bounded by elapsed time and each 15-second heartbeat. Ordinary sessions retain their 30-minute lifetime; long sessions allow the episode duration plus 30 minutes so continuous viewing does not create an artificial second start at 30 minutes. The existing start/reload deduplication window stays unchanged. Previously accepted episodes remain readable if account configuration later changes; future uploads must meet the current policy.

Validation uses disposable local accounts, real long video fixtures, Node and Cloudflare media validators, chunked completion/replay, role changes during validation, additive migration/restart checks, long progress/analytics and ordinary creator rejection. Production verification must not create accounts, upload media or authenticate a fabricated owner session. Preserve existing Worker settings and the original database/media bindings during release.
